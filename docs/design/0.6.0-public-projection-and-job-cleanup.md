## Overview

The 0.6 prerelease line shipped a staged pipeline (resolve → discover → select → lookup → acquire → decode → unseal → finalize → project) and a new job surface (`read`, `Request`/`extract`/`extract_report`, `from_path`, `header`, `profiles`) next to the v0.5.9 compatibility bridge.

The defects that remain are not engine-shaped. They are **projection and job-model** defects:

- isolation (CHIPS partitions, Firefox containers) is discarded before `header()` — and discarded by the snapshot job even though the layer beneath it preserves it;
- one `Request` value means `LegacyFirstProfile` in `extract` and `AllProfiles` in `extract_report`;
- session cookies are inferred from "you passed a profile query";
- five request types carry five copies of the same execution knobs;
- `ProfileSelection::All` is legal on one job of three and a runtime error on the other two;
- three path request types cover what is really two jobs;
- `ChromiumPathRequest::new()` defaults to a strategy that cannot succeed on Windows;
- `ReadResult.browser_id()` uses an empty-string sentinel.

0.6.0 keeps the pipeline, the registry, the report DTO at `schema_version: 1`, and ADR 0004's snapshot/view split. It replaces the *prerelease* job surface with one coherent request model, and leaves the *stable* v0.5.9 surface deprecated but intact.

## Why 0.6.0 and not 0.7.0

Revision 1 and 2 of this document targeted 0.7.0, on the assumption that the 0.6 job API was shipped law that needed a deprecation window. **It is not.** Diffing the public-API snapshots between `v0.5.9` and the current tree:

- **559 items added** since the last stable release, **1 removed**.
- Absent from stable v0.5.9 entirely: `Request`, `extract`, `extract_report`, `read`, `ReadRequest`, `ReadResult`, `ReadWarning`, `from_path`, `FromPathRequest`, `header`, `profiles`, `RequestError`, `StopReason`, `FaultKind`, `CancellationHandle`, and the whole `direct_path` module (`DirectPathRequest`, `ChromiumPathRequest`, `ChromiumCredentialSource`, `DirectPathError`).

Every symbol this design restructures is prerelease-only. Timeouts and cancellation do not exist in stable at all. So the migration apparatus in revisions 1–2 — before/after tables, deprecation choreography, "silent shrink" risks — was aimed at an audience that does not exist. Shipping a whole stable 0.6 whose job was to carry warnings about an API nobody received, and *then* fixing it in 0.7, buys nothing.

Two further facts settle it:

1. **`rookie-rs/public-api/deprecated-items.json` stamps all 36 bridge deprecations `since: "0.6.0"`.** Deprecating and deleting in the same release gives users no version in which the warning is visible. The bridge must therefore survive 0.6.x and be deleted in 0.7.0 — which is exactly the constraint this design now works under.
2. **The prerelease channel is the deprecation window.** Let the corrected API sit in prerelease before cutting a stable release. No stable release is needed to warn about an unshipped API.

### What must be preserved

The compatibility target is **v0.5.9**, not "the 0.5.6 API". 0.5.7–0.5.9 added real public surface, and all of it stays working through 0.6.x:

| Preserved from v0.5.9 | Treatment in 0.6.0 |
| --- | --- |
| Named helpers (`chrome`, `firefox`, `brave`, …), `load`, `browser`, `any_browser` | Deprecated, working. `browser` still needs a `#[deprecated]` — it is missing from the contract. |
| `*_based` family, `chrome_profile`, `firefox_profile(s)`, `MozillaProfile` | Already deprecated, working |
| `config` module, `CONFIG`, `CookieToString` | Already deprecated, working |
| `browser_report`, `load_report`, `browser_profiles`, `chrome_profiles`, `supported_browsers` | **Not deprecated.** These are the good registry-backed 0.5.9 API. Signatures unchanged; `_with` twins added for execution control. |
| `ExtractionReport` / `ProfileDescriptor` / DTO `schema_version: 1` | Unchanged |
| `Cookie`, `CookieContext`, `DetailedCookie` | Unchanged fields; additive derives |
| Windows App-Bound v20 (0.5.8) | Unchanged capability; gains a runtime policy |

### The one deliberate stable break

`rookie_cookies::Result` is `anyhow::Result` today. 0.6.0 redefines it as `Result<T, Error>`. A stable caller who wrote `fn f() -> rookie_cookies::Result<Vec<Cookie>>` around a legacy function breaks.

Mitigation, and the reason this is acceptable:

- `pub use anyhow;` (the module) stays, deprecated, so `rookie_cookies::anyhow::Result` still resolves.
- Legacy functions keep returning `anyhow::Result<T>`, spelled explicitly rather than through the alias. They are unaffected.
- `Error: std::error::Error + Send + Sync + 'static`, so `?` from the new API into an `anyhow` call site still works via `anyhow`'s blanket `From`.

Net break: one type alias name. It is listed in Risks and gets a CHANGELOG callout.

## What already landed

Revisions 1–2 listed C1–C7 as unlanded prerequisites. Verified against the tree, most are done. This design builds on them rather than restating them.

| Item | Status | Evidence |
| --- | --- | --- |
| C1 — mid-flight stop discarded | **Landed** | `flatten_selected_report_cookies` checks `termination` and returns `BoundaryStop` (`lib.rs`) |
| C2 — profile-scoped `read` resets its deadline | **Landed** | `read` calls `profile_extraction_report_with_runtime(.., &runtime)`; no second `Request` (`read.rs`) |
| C3/C4 — App-Bound deadline + parent env mutation | **Landed** | #297: runtime threaded through `get_keys`/injection/impersonation; explicit UTF-16 env block, no `set_var` |
| C5 — conflicting `from_path` credential selectors | **Landed** | #298, bindings reject before opening the file |
| C6 — `header` omits send-time expiry | **Landed** | `header_at` filters on `is_unexpired(cookie, now_epoch)` (`read.rs`) |
| C7 — profile-scoped warnings lose categories | **Landed** | typed `ReadWarningCode` fold, `harvest_report_warnings` (`read.rs`) |
| A2 — binding error identity | **Largely landed** | #298 structured diagnostics in Python/Node |

Three defects **introduced or left open** by that work, which this design closes:

1. **`read` with a profile still flattens a report**, so the snapshot cannot carry isolation and cannot honor a session policy. C2 fixed the deadline; it did not change the route. See [The snapshot seam](#the-snapshot-seam).
2. **A typed value is round-tripped through a string to classify it.** `report_build` maps `Termination` (enum) → `TerminationCode` (open string newtype, for the wire); `flatten_selected_report_cookies` then does `report.termination.as_str()` and matches string literals, with an `anyhow::bail!` fallback for a case its own producer cannot emit. This is the "never classify by parsing strings" rule, broken internally. PR 1 restores the typed path.
3. **`anyhow::bail!("no selected cookie source succeeded")` is still untyped**, so no `EngineError` code but `engine_failure` is reachable. PR 1 adds typed causes.

## Goals & Non-Goals

### Goals

1. One coherent **request model**: `Source × Shape`, with execution control composed once, not copied five times.
2. Make `DetailedCookie` the native snapshot representation on **both** source axes; keep eight-field `Cookie` as a projection.
3. Replace `header(url)` with `header(&SendContext)` that is send-safe and never merges isolation partitions.
4. One `#[non_exhaustive]` public `Error` with `Request` / `Stopped` / `Source` / `Engine`.
5. Make illegal selections **unrepresentable** rather than runtime errors.
6. Require a valid platform credential strategy when constructing a Chromium path request.
7. Replace empty-string result identity with `Option`.
8. Preserve the v0.5.9 surface, deprecated, through 0.6.x.
9. Specify Python, Node, and CLI in the same naming scheme — not "Rust only, bindings TBD".

### Non-goals

- Rewriting acquire/decode/unseal/finalize.
- Schema v2 report counters (A6). 0.6 mitigates in-schema.
- Device Bound Session Credentials; changing the App-Bound native payload format.
- A public `get(url)` or a crate-root Rust `report()`.
- Making `http.cookiejar` / Netscape isolation-aware — those formats cannot represent CHIPS or containers.
- Adding a public-suffix list. `header`'s site comparison is (scheme, host); browser-exact eTLD+1 same-site is out of scope.
- Browser-exact CHIPS: `has_cross_site_ancestor` is retained on the snapshot but not gated on during send-match.
- Deleting the v0.5.9 bridge. That is 0.7.0.

## Proposed Design

### 0. The request model

This is the section revisions 1–2 lacked, and it is why they multiplied duplication instead of removing it.

**Today there are five request types, and every one carries its own `timeout` and `cancellation`:**

| Type | selector | domains | include_expired | credentials | locked_db |
| --- | --- | --- | --- | --- | --- |
| `Request` | browser + profile | ✓ | — | — | — |
| `ReadRequest` | browser + profile | — | ✓ | — | — |
| `FromPathRequest` | path | — | ✓ | ✓ (`Option`) | — |
| `ChromiumPathRequest` | path | ✓ | — | ✓ | ✓ |
| `DirectPathRequest` | path | ✓ | — | — | — |

Adding `app_bound`, `profiles`, and `session` on top of that — as revisions 1–2 did — writes the same knobs a sixth, seventh, and eighth time.

**There is a latent structure in that table.** `include_expired` and `domains` are perfectly anti-correlated, and they track one axis:

- **Snapshot** shape: unfiltered (no domains), `include_expired`, returns everything the store held → `ReadResult`.
- **Extract** shape: domain-reducible, no `include_expired` (sending an expired cookie is wrong), returns a flat list → `Vec<Cookie>`.
- **Report** shape: domain-reducible, scope may widen to every profile → `ExtractionReport`.

Crossed with the source axis, the whole public job surface is one matrix:

| | Snapshot | Extract | Report |
| --- | --- | --- | --- |
| **One browser** | `ReadRequest` → `read` | `ExtractRequest` → `extract` | `ReportRequest` → `extract_report` |
| **One path** | `FromPathRequest` → `from_path` | `PathExtractRequest` → `extract_from_path` | — |
| **Every browser** | — | — | `LoadReportRequest` → `load_report_with` |

Five types, each justified by a cell, replacing five types that were an ad-hoc sampling of the same space.

#### Shared state, composed once

```rust
/// Crate-private. Not exported, not in the public-api snapshot, not modeled
/// by bindings. Generic over the selection type so the report job can widen
/// to every profile while single-profile jobs cannot.
struct BrowserTarget<S> {
    browser_id: String,   // empty => RequestError::MissingBrowser at job time
    selection: S,         // ProfileSelection, or ReportScope for reports
    session: SessionPolicy,
}

/// Crate-private. Shared by both path jobs.
struct PathTarget {
    path: PathBuf,
    credentials: Option<ChromiumCredentialSource>,
    locked_database_policy: ChromiumLockedDatabasePolicy,
}
```

Public request types become three fields each:

```rust
pub struct ReadRequest        { target: BrowserTarget<ProfileSelection>, include_expired: bool,           control: ExecutionControl }
pub struct ExtractRequest     { target: BrowserTarget<ProfileSelection>, domains: Option<Vec<String>>,    control: ExecutionControl }
pub struct ReportRequest      { target: BrowserTarget<ReportScope>,      domains: Option<Vec<String>>,    control: ExecutionControl }
pub struct FromPathRequest    { target: PathTarget,                      include_expired: bool,           control: ExecutionControl }
pub struct PathExtractRequest { target: PathTarget,                      domains: Option<Vec<String>>,    control: ExecutionControl }
```

**What this does and does not buy, stated honestly.** It removes duplicated *state*, duplicated *validation* (one `resolve()` on `BrowserTarget`, one credential check on `PathTarget`), and duplicated *binding option parsing*. Rust has no delegation, so each public type still needs one-line forwarding methods (`pub fn profile(mut self, q) -> Self { self.target = self.target.profile(q); self }`). Those are mechanical and can be generated by a small declarative macro if the repetition is judged worth removing; that is an implementation choice, not a contract.

**`ReadRequest` and `ExtractRequest` are deliberately not merged.** The one field that differs is the ADR 0004 invariant: a domain-filtered snapshot makes `header()` silently wrong, because it omits parent-domain cookies the browser would send. Keeping them separate is what makes that invariant a type fact rather than a documentation request.

#### Selection: `All` becomes unrepresentable

```rust
/// Selects exactly one profile. Cannot express "every profile".
#[non_exhaustive]
#[derive(Clone, Debug, PartialEq, Eq, Default)]
pub enum ProfileSelection {
    /// First legacy-eligible profile.
    #[default]
    LegacyFirst,
    /// ADR 0003 query: opaque profile_id, display name, directory name, or non-lossy path.
    Query(String),
}

/// Report scope. Only reports may widen to every profile.
#[non_exhaustive]
#[derive(Clone, Debug, PartialEq, Eq, Default)]
pub enum ReportScope {
    /// Every installation and profile. The v0.5.9 `browser_report(id, None)` meaning.
    #[default]
    AllProfiles,
    /// One profile, chosen the same way single-profile jobs choose.
    One(ProfileSelection),
}
```

This deletes `RequestError::SnapshotAllProfiles` and `RequestError::FlattenAllProfiles` outright, along with their codes, their binding mappings, and their tests. A3 — "the same `Request` value selects differently in `extract` and `extract_report`" — is closed **by type**: you cannot hand one value to both without a conversion that states the scope.

```rust
impl From<ExtractRequest> for ReportRequest {
    /// Same browser, same profile, same domains, same control — reported
    /// rather than flattened. Scope narrows to `One`, never widens.
    fn from(request: ExtractRequest) -> Self { /* ... */ }
}
```

`ReportRequest::browser(id)` defaults to `AllProfiles`, which is exactly what stable `browser_report(id, None, domains)` means. So the convenience wrapper keeps its semantics with no risk of the silent all-profiles→first-profile shrink that revisions 1–2 had to guard against in prose.

```rust
pub fn extract(request: ExtractRequest) -> Result<Vec<Cookie>>;
pub fn extract_report(request: ReportRequest) -> Result<report::ExtractionReport>;

// v0.5.9, unchanged, undeprecated. Sugar for ReportRequest::browser(id).
pub fn browser_report(
    browser_id: &str,
    profile_id: Option<&str>,
    domains: Option<Vec<String>>,
) -> Result<report::ExtractionReport>;
```

#### Path jobs: three types become two

`DirectPathRequest` is `ChromiumPathRequest` minus credentials minus locked-database policy. `FromPathRequest` already carries `credentials: Option<_>` and nearly covers both. The "Chromium-only vs. sniff the format" distinction does not belong in the type — it belongs in the credential value, which is where §8's constructors already put it.

| Deleted (prerelease-only) | Replacement |
| --- | --- |
| `DirectPathRequest`, `cookies_from_path` | `PathExtractRequest`, `extract_from_path` |
| `ChromiumPathRequest`, `chromium_cookies_from_path` | `PathExtractRequest` with Chromium credentials |
| `chromium_cookies_from_path_detailed` | `from_path(...).detailed_cookies()` |

This also removes a live asymmetry: `ChromiumPathRequest` has no `include_expired` while `FromPathRequest` does. Under the matrix, `include_expired` belongs to the snapshot shape on both sources, and `domains` to the extract shape on both.

**Deprecation notes must be updated in the same PR.** Eight entries in `deprecated-items.json` point callers at `DirectPathRequest` / `ChromiumPathRequest` / `cookies_from_path` / `chromium_cookies_from_path_detailed` (`any_browser`, `chromium_based`, `chromium_based_detailed`, `chromium_based_with_browser_id`, `chromium_based_detailed_with_browser_id`, `firefox_based`, `safari_based`, `internet_explorer_based`). Renaming the target without rewriting the note leaves the contract pointing at symbols that no longer exist — and `check-public-api.py` validates the contract, so this is a CI failure, not just a docs wart.

**Capability note.** `chromium_cookies_from_path_detailed` returns domain-reducible *detailed* cookies today; after the collapse, detailed output comes from `from_path`, which is unfiltered. Callers who need both isolation and a domain filter walk the snapshot themselves or use `extract_report`. This is the same rule the browser axis already follows and it applies to a prerelease API, so it costs nothing shipped — but it is a real narrowing and is listed in Risks.

### The snapshot seam

`read` must stop flowing through `ExtractionReport`.

The earlier 0.6 prerelease routed profile-scoped `read` through the report builder (`read.rs`: `profile_extraction_report_with_runtime` → `flatten_selected_report_cookies`). #298 fixed the deadline (C2) and the swallowed stop (C1) on that route, but not the route itself.

The report projector emits the eight-field `Cookie` — `report_build.rs` calls `into_cookie_with_semantics`, and `SourceExtraction.cookies` is `Vec<Cookie>` because the DTO is frozen at `schema_version: 1`. A snapshot flattened out of a report has **already lost `CookieContext`**. If 0.6.0 kept that route, `read(...).profile("Default")` would return `DetailedCookie`s whose context is `Default::default()`, `header()` would see no isolated cookies, `IncompleteSendContext` would never fire, and partitions would merge — on the path this design recommends.

The same defect exists on the path axis, and there the evidence is sharper: `chromium_cookies_from_path_detailed` already returns `Vec<DetailedCookie>`, while `from_path` → `ReadResult` → `Vec<Cookie>`. **The crate has the detailed projection and throws it away at the job boundary, on both source axes.**

0.6.0 adds one crate-private snapshot seam, shared by both selections, that never builds a report:

```rust
pub(crate) fn browser_snapshot_with_runtime(
    browser_id: &str,
    selection: registry::ProfileSelection, // LegacyFirstProfile | ProfileId — never AllProfiles
    session: SessionPolicy,
    runtime: &BoundaryRuntime<'_>,
) -> Result<SnapshotOutcome>;

pub(crate) struct SnapshotOutcome {
    pub(crate) cookies: Vec<DetailedCookie>,
    pub(crate) warnings: ReadWarningCounts,
    pub(crate) profile_id: Option<String>,
    pub(crate) termination: Termination, // typed; a stop becomes Error::Stopped
}
```

It stops at `FinalizedCookieRecord` and projects with `into_detailed_cookie_with_semantics` for **both** selections. The `LegacyFirstProfile` arm already exists as `legacy::project_canonical_detailed_outcome_with_runtime`; the `ProfileId` arm is the new code this design requires.

`extract` and `extract_report` keep the report route and the eight-field projection. They differ on session: `extract_report` / `load_report` always retain session sources, while `extract` is a flatten and honors `SessionPolicy` like `read` does.

This also makes C2 structural rather than a rule to remember — there is no second request to build.

### 1. `DetailedCookie` as the snapshot representation

`Cookie`, `CookieContext`, and `DetailedCookie` already exist and are stable API. 0.6.0 keeps their fields and makes `DetailedCookie` what the snapshot stores.

```rust
// Additive derives: Clone + PartialEq + Eq + Hash on Cookie so bindings stop
// hand-copying. Debug still redacts `value`.

pub struct ReadResult {
    cookies: Vec<DetailedCookie>,  // native snapshot
    projected: Vec<Cookie>,        // eight-field projection, built once at construction
    warnings: Vec<ReadWarning>,
    browser_id: Option<String>,    // None on from_path
    profile_id: Option<String>,
}

impl ReadResult {
    /// Compatibility projection: isolation discarded. Borrowed, not rebuilt
    /// per call — bindings call this on every `as_list()`.
    pub fn cookies(&self) -> &[Cookie];
    /// Recommended accessor. Isolation retained.
    pub fn detailed_cookies(&self) -> &[DetailedCookie];
    pub fn into_cookies(self) -> Vec<Cookie>;
    pub fn into_detailed_cookies(self) -> Vec<DetailedCookie>;
    pub fn warnings(&self) -> &[ReadWarning];
    pub fn browser_id(&self) -> Option<&str>;
    pub fn profile_id(&self) -> Option<&str>;
    /// Send-safe Cookie header. Never mutates the snapshot.
    pub fn header(&self, context: &SendContext) -> Result<String>;
}
```

`cookies()` keeps its `-> &[Cookie]` signature; this is settled, not left to the implementer. **Cost, stated plainly:** the snapshot holds two copies of every name and value. For a large Chrome profile that is real memory, and it is the price of keeping `cookies()` a free borrow for bindings. `into_cookies` / `into_detailed_cookies` move instead of duplicating. `ReadResult`'s existing rustdoc already promises values are "not duplicated by" the projection — that promise must be rewritten, not silently broken.

**A7 (malformed required host identity):** snapshot and `extract` **omit** rows whose domain is empty after decode, and increment `ReadWarning` / source issue code `malformed_host_identity`. They do not emit `Cookie { domain: "", .. }`. Unknown optional isolation fields stay `None` and do not drop the row.

`extract` returns a bare `Vec<Cookie>` and therefore has **no channel to report the omission**. That is the contract, not an oversight: callers who need the count use `read` or `extract_report`.

### 2. `SendContext` for send-safe header selection

```rust
#[non_exhaustive]
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub enum ResourceKind { Navigation, #[default] Subresource }

#[non_exhaustive]
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub enum MethodClass { #[default] Safe, Unsafe }

/// View inputs for `ReadResult::header`. Never applied to stored cookies.
///
/// `Debug` is hand-written and redacts `url` / `top_level_site` through
/// `header_filter::redact_url`: a URL may carry userinfo, and this is the
/// type a caller is most likely to log.
pub struct SendContext {
    url: String,                       // required
    top_level_site: Option<String>,
    resource: ResourceKind,            // default Subresource
    method: MethodClass,               // default Safe
    user_context_id: Option<u32>,
    private_browsing_id: Option<u32>,
    now: Option<SystemTime>,           // None = SystemTime::now() at header() time
}

impl SendContext {
    pub fn url(url: impl Into<String>) -> Self;
    pub fn top_level_site(self, site: impl Into<String>) -> Self;
    pub fn resource(self, kind: ResourceKind) -> Self;
    pub fn navigation(self) -> Self;
    pub fn subresource(self) -> Self;
    pub fn method(self, class: MethodClass) -> Self;
    pub fn user_context_id(self, id: u32) -> Self;
    pub fn private_browsing_id(self, id: u32) -> Self;
    pub fn now(self, now: SystemTime) -> Self;
}
```

| Field | Selector token | Demanded when the snapshot contains |
| --- | --- | --- |
| `url` | — | always (`http`/`https` only; `RequestError::InvalidUrl`, redacted) |
| `top_level_site` | `"top_level_site"` | any cookie with a non-empty `top_frame_site_key` **or** non-empty `partition_key` |
| `resource` | — | affects Lax cross-site only |
| `method` | — | affects Lax cross-site only |
| `user_context_id` | `"user_context_id"` | any cookie with `user_context_id == Some(n)`, `n > 0` |
| `private_browsing_id` | `"private_browsing_id"` | any cookie with `private_browsing_id == Some(n)`, `n > 0` |
| `now` | — | always used for send-time expiry |

`IncompleteSendContext.required` carries exactly these tokens, in table order, deduplicated. They are stable identifiers, not prose.

**Missing vs default.** `CookieContext`'s rustdoc is a shipped contract: a missing field "must not be interpreted as the browser's default partition or container." 0.6.0 honors it on the matching side and narrows it on the gating side; the two must not be conflated:

- **Gating** (does a missing selector raise an error?): only a *positively observed* isolated value counts. `None` and `Some(0)` never demand a selector — otherwise `header` becomes unusable against every browser version whose schema lacks these columns.
- **Matching** (does this cookie go in the header?): a cookie whose relevant field is `None` is unpartitioned/default-container **only when the caller supplied no selector for it**. If the caller passed `user_context_id(2)`, a cookie with `user_context_id: None` is **not** a match — the crate does not know it belongs to container 2, and guessing is how partitions merge.

**Site.** This crate has no public-suffix list and does not gain one. 0.6.0 defines:

> **site** = (scheme, host), compared case-insensitively on host, with the default port elided. Nothing is reduced to eTLD+1.

`https://cdn.example.com` and `https://app.example.com` are therefore **cross-site** to this crate and same-site to a browser. That makes `header` **conservative** for `SameSite=Lax`/`Strict` — it omits cookies a browser would send, never the reverse — which is the right direction for a credential library.

`top_level_site` is parsed by the same `http`/`https` parser as `url`. An unparseable or non-HTTP value is `RequestError::InvalidTopLevelSite { display }` (code `invalid_top_level_site`, redacted), raised in step 1 — not ignored, because ignoring it falls back to the first-party assumption and sends more than the caller asked for.

```text
header(ctx):
  1. Parse ctx.url → GetFilter. Invalid → Error::Request(InvalidUrl).
     Parse ctx.top_level_site if present. Invalid → InvalidTopLevelSite.
  2. Resolve now. Pre-unix-epoch → Error::Request(ClockUnrepresentable).
     Do not map to epoch 0 (that disables expiry).
  3. Classify: for each selector token, the snapshot DEMANDS it iff at least
     one cookie positively observes the corresponding isolated value.
     None and Some(0) never demand.
  4. required = demanded tokens the caller did not supply.
     If non-empty → Error::Request(IncompleteSendContext { display, required }).
     Per-token and per-cookie: ONE partitioned cookie is enough. There is no
     "more than one identity" threshold.
  5. Keep a cookie iff all of:
       a. sendable octets (existing sendable_octets)
       b. RFC domain / path / Secure (existing GetFilter)
       c. send-time expiry: expires.is_none() || expires > now_epoch  (C6, landed)
       d. isolation match (normalization below)
       e. SameSite (table below)
  6. Sort by path length desc, then name asc (earlier 0.6 prerelease header order).
  7. Join `name=value` with "; ".
```

Once the caller **has** supplied a selector, cookies in other partitions or containers are **omitted**, not an error. The error in step 4 exists only for the selector never supplied at all.

**Isolation matching (step 5d).** "Equals `ctx.top_level_site`" is not implementable as string equality: the two engines store partition identity in different encodings and neither is a URL. `cookie_record.rs`'s own tests show Firefox `partition_key` stored as `"(https,example.com)"`, while `top_level_site` is `"https://example.com"`. Comparing those directly matches nothing, so every Firefox dFPI cookie would vanish from every header.

```rust
/// (scheme, host), host lowercased, default port elided.
/// The single comparison space for all partition identity.
struct Site { scheme: String, host: String }

fn site_from_url(raw: &str) -> Result<Site, RequestError>;
fn site_from_firefox_partition_key(raw: &str) -> Option<Site>;       // "(https,example.com[,...])"
fn site_from_chromium_top_frame_site_key(raw: &str) -> Option<Site>; // serialized site or origin
```

- **Firefox `partition_key`**: parse the parenthesized, comma-separated tuple. Field 0 is scheme, field 1 host. Trailing fields (port, foreign-ancestor bit, anything a future Firefox adds) are **ignored for matching** and never cause a parse failure — the tuple is an open vocabulary, and `origin_attributes` retains the verbatim value.
- **Chromium `top_frame_site_key`**: accept the serialized-site form and a bare origin with a port; strip a trailing `/`; elide port 443 for `https`, 80 for `http`.
- A value that parses in neither helper is **not** treated as unpartitioned. It is a non-match against every context and increments an `unparsable_partition_key` warning, so the loss is visible.
- `user_context_id` / `private_browsing_id` compare as integers under the Missing-vs-default rule.
- `has_cross_site_ancestor` is **not** consulted. A cookie set under a same-site ancestor and one set under a cross-site ancestor share a `top_frame_site_key`, so `header` may include a cookie a browser would withhold. Listed as a limitation, not silently dropped.

| `same_site` | Meaning | Sent when |
| --- | --- | --- |
| `2` | Strict | request `Site` == top-level `Site` |
| `1` | Lax | same-site, **or** cross-site ∧ `Navigation` ∧ `Safe` |
| `0` | None | Secure already matched at 5b; sent cross-site |
| `-1` | Unspecified | Treated as Lax (browser default) |

If `top_level_site` is omitted and step 4 did not error, same-site is computed as if the top-level site were the request URL's own `Site` (first-party assumption).

**Stated limitations.** Site is (scheme, host), not eTLD+1, so Lax/Strict is conservative. CHIPS ancestor state is not gated on, so partitioned cookies may be over-included within a matching key. There is one same-site rule, not a schemeful/legacy dual mode. These are the design's answers, not open questions — a caller needing browser-exact behavior needs a browser.

### 3. One typed public error hierarchy

```rust
// rookie-rs/src/error.rs (new module; cohesion, not a line-budget carve)

#[non_exhaustive]
#[derive(Debug)]
pub enum Error {
    Request(RequestError),
    Stopped(StopReason),
    Source(direct_path::DirectPathError),
    Engine(EngineError),
}

#[non_exhaustive]
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct EngineError { code: &'static str, message: String }

pub type Result<T> = std::result::Result<T, Error>;

impl Error {
    pub fn code(&self) -> &'static str {
        match self {
            Self::Request(e) => e.code(),
            Self::Source(e)  => e.code(),
            Self::Engine(e)  => e.code(),
            Self::Stopped(StopReason::TimedOut)          => "timed_out",
            Self::Stopped(StopReason::Cancelled)         => "cancelled",
            Self::Stopped(StopReason::ResourceExhausted) => "resource_exhausted",
        }
    }
    pub fn stop_reason(&self) -> Option<StopReason>;
    #[deprecated(since = "0.6.0", note = "match Error; FaultKind is a two-way FFI split")]
    pub fn fault_kind(&self) -> FaultKind;
}

impl From<RequestError> for Error;
impl From<direct_path::DirectPathError> for Error;

// NOT a public `From`: BoundaryStop is pub(crate). A public impl naming it is
// unusable downstream, a `private_interfaces` candidate, and would render a
// private type's path into rookie-rs/public-api/*.txt.
impl Error { pub(crate) fn stopped(stop: common::deadline::BoundaryStop) -> Self; }
```

`RequestError` grows `IncompleteSendContext { display, required }`, `InvalidTopLevelSite { display }`, `ClockUnrepresentable`, `AppBoundUnavailable { policy }`, `ConflictingCredentialSelectors`, `ConflictingProfileSelection`. It **loses** `SnapshotAllProfiles` and `FlattenAllProfiles` — `ReportScope` makes them unrepresentable. `MissingBrowser` is retained for an empty `browser_id` on every browser job.

**`EngineError` codes.**

| Code | When |
| --- | --- |
| `no_selected_source` | No selected source succeeded, whether none were selected or all failed |
| `no_discovered_source` | Discovery completed, nothing to acquire (snapshot `Err`, report `Ok(no_sources)`) |
| `discovery_failed` | Every detected root failed enumeration on a snapshot/listing job |
| `engine_failure` | Last-resort fallback |

These require typed carriers; they cannot be recovered from today's errors, because `flatten_selected_report_cookies` is a bare `anyhow::bail!` and classifying by parsing `Display` is forbidden. **PR 1** adds a crate-private cause and attaches it at each site:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum EngineCause {
    NoSelectedSource,
    NoDiscoveredSource,
    DiscoveryFailed,
    SourceInspectionFailed,
}
```

The earlier prerelease's `no_selected_source` / `selected_sources_failed` split is folded into one code: the distinction is not observable to a caller and would require the flatten to track states it does not have.

**Stop classification stops round-tripping through a string.** `flatten_selected_report_cookies` currently does `report.termination.as_str()` and matches literals, with a fallback `anyhow::bail!` for a case its own producer cannot emit. The internal path carries the typed `Termination`; `TerminationCode` exists only at the DTO edge. The report-shaped jobs keep emitting the string; the flatten reads the enum.

```rust
fn map_job_error(err: anyhow::Error) -> Error {
    // Order is load-bearing. A BoundaryStop can be wrapped inside a
    // DirectPathError, so the stop must win. Reordering silently
    // reclassifies every timeout under a direct-path job as a Source error.
    if let Some(stop) = err.downcast_ref::<BoundaryStop>() { return Error::stopped(*stop); }
    if let Some(req)  = err.downcast_ref::<RequestError>() { return Error::Request(req.clone()); }
    if let Some(src)  = err.downcast_ref::<direct_path::DirectPathError>() {
        if src.invalid_source_reason() == Some(&InvalidCookieSourceReason::SourceInspectionFailed) {
            return Error::Engine(EngineError::from_cause(EngineCause::SourceInspectionFailed, &err));
        }
        return Error::Source(src.clone());
    }
    if let Some(cause) = err.downcast_ref::<EngineCause>() { return Error::Engine(EngineError::from_cause(*cause, &err)); }
    Error::Engine(EngineError::from_anyhow(err))
}
```

`DirectPathError::InvalidSource` and
`InvalidCookieSourceReason::SourceInspectionFailed` remain public and keep the
stable `source_inspection_failed` code. Only the outer classification changes:
typed I/O/SQLite inspection failures are operational `Engine` faults, while
the other direct-path reasons remain caller-correctable `Source` faults. No
diagnostic text is parsed, the internal `anyhow` chain retains the underlying
typed cause until the public edge sanitizes it, and the `BoundaryStop` arm
continues to win before either classification.

`EngineError::from_anyhow` is the last-resort mapper only: `code` is always `engine_failure`; `message` is the sanitized chain `Display` (never cookie values, key bytes, or `HBD_ABE_ENC_B64`; paths redacted); the `anyhow` chain is **not** retained as `Error::source()`, which returns the nested `RequestError`/`DirectPathError` and `None` for `Engine`.

Free `stop_reason` / `fault_kind` change from `&anyhow::Error` to `&Error` and are deprecated in favor of the methods. Both are deprecated *and* delegate to deprecated methods, so they need `#[allow(deprecated)]` — this crate denies warnings in CI.

**Legacy functions keep `anyhow::Result`.** They convert at their own edge via `anyhow`'s blanket `From`. Two error types coexist through 0.6.x; 0.7.0 leaves one.

| Surface | Stop with records already collected |
| --- | --- |
| `read`, `extract`, `from_path`, `extract_from_path` | `Err(Error::Stopped(_))` |
| `extract_report`, `browser_report`, `load_report` | `Ok(report)` with `termination` ≠ `completed` |

### 4. Session policy

```rust
#[non_exhaustive]
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub enum SessionPolicy { #[default] PersistentOnly, IncludeSession }
```

Orthogonal to selection. Chromium has no separate session source in the registry; the flag is then a no-op.

**Where the gate lives.** "Acquired only when `IncludeSession`" is an **acquire-time** rule, not a post-projection filter, and the mechanism is named so it cannot be implemented as the latter. The Gecko registry already tags candidates by role — `candidate.role == CookieSourceRoleId::session()`. `browser_snapshot_with_runtime` drops session-role candidates from the selected set **before lookup**, so `PersistentOnly` performs no session I/O at all.

The distinction matters twice. "Project then drop" would still open `sessionstore.js` / `recovery.jsonlz4` — files the caller asked the crate not to touch — and would still need a filter `flatten_selected_report_cookies` does not have. And because the earlier prerelease's profile-scoped `read` reached cookies *through* a report, a design that kept that route would honor `PersistentOnly` without a profile and silently ignore it with one, on exactly the API the migration guide points session-importing callers at.

`extract` is where both worlds meet: it produces a bare list (snapshot-shaped output) by flattening a report (always-session machinery). It honors `SessionPolicy`. Concretely, the internal report builder takes the same session parameter; `extract_report` and `load_report` pass `IncludeSession` unconditionally, `extract` passes the request's policy. The DTO is unchanged either way — a report built for `extract` under `PersistentOnly` simply has no session sources, the same as a profile that has none.

`read(ReadRequest::browser("chrome").include_session())` is **new**: first legacy profile *with* session, without naming it. The earlier prerelease could not express that without also switching flatten policy.

### 5. One `ExecutionControl` composed into every I/O job

```rust
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct ExecutionControl {
    timeout: Option<Duration>,                 // None = DEFAULT_EXTRACTION_BUDGET (30s)
    cancellation: Option<CancellationHandle>,  // None = never cancelled by handle
    app_bound: AppBoundPolicy,                 // default Disabled
}

impl Default for ExecutionControl { /* None, None, Disabled */ }
impl ExecutionControl {
    pub fn timeout(self, timeout: Duration) -> Self;
    pub fn cancellation(self, handle: CancellationHandle) -> Self;
    pub fn app_bound(self, policy: AppBoundPolicy) -> Self;
}
```

`Debug` prints timeout, cancelled-bit, and policy. No secrets.

The derives work only because `CancellationHandle` already carries hand-written impls: a `Debug` printing the cancelled bit, and a `PartialEq` comparing **handle identity** — whether two handles are clones — not cancellation state. `ExecutionControl: Eq` inherits that meaning, and it becomes a public contract on a new type, so rustdoc says it: two controls with identical timeouts and policies but different handles are **not** equal.

**Builder precedence.** `.timeout` / `.cancellation` / `.app_bound` edit fields of the embedded control. `.execution(control)` replaces the control **wholesale**, discarding an earlier `.timeout(...)`. Last writer wins, but the two knobs are at different granularity, so `.execution` rustdoc says so and the recommended order is `.execution(...)` first, field setters after.

**Composition, including the stable listing and aggregate jobs.** v0.5.9 `load_report(Option<Vec<String>>)`, `browser_profiles(&str)`, `chrome_profiles()` take no control and their signatures are stable. They keep them, and gain `_with` twins:

```rust
#[derive(Clone, Debug, Default, PartialEq, Eq)]
pub struct LoadReportRequest { domains: Option<Vec<String>>, control: ExecutionControl }

pub fn load_report(domains: Option<Vec<String>>) -> Result<report::ExtractionReport>; // v0.5.9, kept
pub fn load_report_with(request: LoadReportRequest) -> Result<report::ExtractionReport>;

pub fn browser_profiles(browser_id: &str) -> Result<Vec<report::ProfileDescriptor>>; // v0.5.9, kept
pub fn browser_profiles_with(browser_id: &str, control: ExecutionControl) -> Result<Vec<report::ProfileDescriptor>>;

pub fn chrome_profiles() -> Result<Vec<report::ProfileDescriptor>>;                   // v0.5.9, kept
pub fn chrome_profiles_with(control: ExecutionControl) -> Result<Vec<report::ProfileDescriptor>>;

pub fn profiles(browser_id: &str) -> Result<Vec<report::ProfileDescriptor>>;          // alias, kept
pub fn profiles_with(browser_id: &str, control: ExecutionControl) -> Result<Vec<report::ProfileDescriptor>>;

pub fn supported_browsers() -> Result<Vec<report::BrowserDescriptor>>;  // catalog: no I/O, no control
```

There is **no `ProfilesRequest` type.** Listing has no selection or session policy to carry; an envelope struct would be ceremony.

`load_report` fan-out (`DEFAULT_FAN_OUT_WIDTH = 4`) shares the one runtime, as today. Concurrent *different* jobs may carry different `AppBoundPolicy` values; #297 already passes the encrypted blob in a child environment block, so policies cannot collide via parent env — and 0.6.0 must not reintroduce `set_var`.

### 6. Caller-selected `AppBoundPolicy`

```rust
/// Per-job Windows App-Bound (v20) recovery policy.
/// Request-local and immutable after the job starts. Not an environment variable.
#[non_exhaustive]
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub enum AppBoundPolicy {
    /// No injection, no browser process spawn, no process enumeration,
    /// no SYSTEM impersonation. v20 rows remain unreadable.
    #[default]
    Disabled,
    /// Reflective COM injection only (unprivileged, Chrome 127+).
    InjectionOnly,
    /// Injection, then elevated SYSTEM impersonation fallback.
    AllowElevatedFallback,
}
```

Bindings expose the same three strings: `disabled`, `injection_only`, `allow_elevated_fallback`. No boolean combinations.

| Host | `feature = "appbound"` | Policy | Behavior |
| --- | --- | --- | --- |
| Non-Windows | any | any | **Ignored** (no-op) |
| Windows | off | `Disabled` | OK |
| Windows | off | non-`Disabled` | `Err(AppBoundUnavailable)` — **only if the job reaches v20 recovery** |
| Windows | on | `Disabled` | No native ABE work at all |
| Windows | on | `InjectionOnly` | Injection only; on failure v20 stays unreadable |
| Windows | on | `AllowElevatedFallback` | #297 attempt order, with deadline polling and child env block |

**`AppBoundUnavailable` is raised at the v20 lookup, not the job edge.** A job-global reject would fail Firefox `read`, `profiles`, and Gecko `from_path` on a Windows `no-default-features` build — jobs that never call ABE. That configuration is a published surface (`windows-no-default-features.txt`), so a caller doing a mixed-browser sweep with one shared `ExecutionControl { InjectionOnly }` could not read Firefox at all.

**`ROOKIE_E2E_APPBOUND_MODE` must stop steering production.** `get_keys` reads it in production code and branches on `elevated_only`. Left beside the new policy, a process environment variable can still override `AllowElevatedFallback` or `Disabled` — the process-global steering C4 and A8 exist to remove, reintroduced through the back door. PR 2 gates it behind `cfg(test)` (or a test-only feature) and documents that it can never override `Disabled` or widen a policy.

### 7. Chromium path credentials that cannot be invalid

**Today:** `ChromiumPathRequest::new(path)` sets `credentials: Automatic`. Automatic works on Unix (historical identity probe) and **always errors on Windows** (`MissingLocalStateFile`). The defect is the default, not "direct path fails on Windows."

```rust
#[non_exhaustive]
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ChromiumCredentialSource {
    PlaintextOnly,
    /// Unix Keychain / libsecret identity from the registry. Invalid on Windows.
    BrowserId(String),
    /// Windows Local State file. Invalid on Unix.

}

impl PathExtractRequest {
    // No new(). Credentials are chosen at construction.
    pub fn plaintext(path: impl Into<PathBuf>) -> Self;
    #[cfg(unix)]    pub fn unix_identity(path: impl Into<PathBuf>, browser_id: impl Into<String>) -> Self;
    #[cfg(windows)] pub fn windows_local_state(path: impl Into<PathBuf>, local_state: impl Into<PathBuf>) -> Self;
    /// No credentials: sniff the format; Chromium is plaintext-capable only.
    pub fn sniff(path: impl Into<PathBuf>) -> Self;

    pub fn domains(self, domains: Option<Vec<String>>) -> Self;
    pub fn locked_database_policy(self, policy: ChromiumLockedDatabasePolicy) -> Self;
    pub fn timeout(self, timeout: Duration) -> Self;
    pub fn cancellation(self, handle: CancellationHandle) -> Self;
    pub fn app_bound(self, policy: AppBoundPolicy) -> Self;
    pub fn execution(self, control: ExecutionControl) -> Self;
}

impl FromPathRequest {
    pub fn new(path: impl Into<PathBuf>) -> Self;   // sniff; no credentials
    pub fn chromium_plaintext(self) -> Self;
    pub fn chromium_browser_id(self, id: impl Into<String>) -> Self;
    pub fn chromium_local_state(self, local_state: impl Into<PathBuf>) -> Self;
    pub fn include_expired(self, yes: bool) -> Self;
    // control setters as above
}
```

**Where the `cfg` lives — a CI constraint, not a style note.** `cargo run -p xtask -- check-cfg-locations` runs on every push against `cfg-location-allowlist.toml`. A `grandfathered` file fails if its platform-`cfg` count goes **up**; a file absent from the allowlist may not carry platform `cfg` at all. Two parts of a naive implementation break it:

- `direct_path/mod.rs` is grandfathered with a fixed ceiling; adding `unix_identity` / `windows_local_state` there raises it.
- `read.rs` is **not in the allowlist** and has zero platform `cfg` today (its only `cfg` is `#[cfg(test)]`). A `#[cfg(unix)]` method on `FromPathRequest` there is a hard failure, and adding `read.rs` as a `leaf` would misuse that tier — a cfg-gated inherent method is the scattered per-item pattern the tiers exist to ratchet.

So the split is deliberate: **`PathExtractRequest` carries the cfg-gated constructors, defined in the already-allowlisted `direct_path/{linux,macos,windows,unsupported}.rs` leaves** and re-exported through `mod.rs`'s existing selection gate — no ceiling moves. **`FromPathRequest` stays portable** with runtime validation, so `read.rs` gains no platform `cfg`. That is not a compromise: `FromPathRequest` is the type bindings and the CLI wrap, and they need a portable options object with runtime validation regardless.

`cfg-location-allowlist.toml` is in the PR's file list so that if a ceiling must move, the one-line reason the allowlist header requires lands with it.

**Sniffing without credentials cuts both ways per platform.** On Unix, `cookies_from_path` on a Chromium DB probes today, so 0.6.0 removes a capability: plaintext still works, encrypted needs an explicit browser id. On Windows, `cookies_from_path` returns `MissingLocalStateFile` for `ChromiumSqlite` **before** attempting extraction, so even a fully plaintext Cookies DB fails today — under the 0.6.0 rule that call returns `Ok`. Both halves belong in the notes; only the Unix half is a restriction.

### CLI

Job subcommands only. Cooperative SIGINT/SIGTERM is installed on **every** extraction/report/listing subcommand.

```text

    --timeout-secs 10 --app-bound injection-only --format detailed
rookie-cookies from-path PATH --local-state-path LOCALSTATE --app-bound disabled
rookie-cookies header --url https://example.com/ --browser chrome --profile Default \
    --top-level-site https://example.com --resource navigation --include-session
rookie-cookies report --browser chrome                    # ReportScope::AllProfiles
rookie-cookies report --browser chrome --profile Default
rookie-cookies report                                     # load_report
rookie-cookies profiles chrome --timeout-secs 5
rookie-cookies browsers
```

Shape changes beyond the deleted legacy path:

| Subcommand | Earlier 0.6 prerelease | Corrected 0.6 API |
| --- | --- | --- |
| `report` | `report <BROWSER>` — required positional | `report [--browser <ID>]` — optional flag; omitted means `load_report`. Adds `--select`, `--timeout-secs`, `--app-bound`. `report chrome` no longer parses. |

| `profiles` | `profiles <BROWSER>` | unchanged shape; adds `--timeout-secs` |
| `read` / `from-path` | `--format netscape\|json` | adds `--format detailed`, `--select`, `--include-session`, `--app-bound`, `--domains` on `from-path` |

**`--format detailed`.** Without it, isolation would exist on the CLI only as an invisible side effect of `header` matching, and an operator could not inventory CHIPS partitions or Firefox containers from the surface most likely to be used for exactly that. It emits JSON objects carrying the eight `Cookie` fields plus a `context` object. `netscape` and `json` are unchanged eight-field projections, because those formats cannot represent partitions.

`--key-path` becomes `--local-state-path`. Removed: the no-subcommand `load()` path, `--browser` flat extract, top-level `--path`. Warnings go to stderr; cookies/header/JSON to stdout.

## Security & Privacy

Cookies are credentials.

- **`Debug` redaction** on `Cookie` / `DetailedCookie` / `ReadResult` / `SendContext` remains or is added. Adding `Clone`/`Eq` does not weaken it.
- **`SendContext` / `InvalidUrl` / `InvalidTopLevelSite`** never retain userinfo (`header_filter::redact_url`).
- **No cookie values in logs, issues, warnings, or `EngineError.message`.**
- **`AppBoundPolicy::Disabled` default** avoids unsolicited process injection and SYSTEM impersonation on new APIs.
- **Never `std::env::set_var` for `HBD_ABE_ENC_B64`.** #297's child environment block stays; 0.6.0 must not regress it.
- **`jar()` / Netscape / `cookies()`** are isolation-unaware projections. Document them as RFC/HTTP client helpers, not browser-equivalent jars: CHIPS/container cookies in a merged `CookieJar` can leak across partitions if the caller sends them. `header(SendContext)` is the send-safe API.
- **`ReportScope` makes cross-profile flattening a compile error**, so several people's Chrome profiles cannot be concatenated into one header by construction.
- **Malformed empty-domain rows are dropped** (A7) so they cannot be sent as host-less cookies.
- **`include_expired` is inventory-only**; `header` always applies send-time expiry.
- **Locked-database process shutdown** stays off bindings and CLI.

A caller who sets `AllowElevatedFallback` is requesting SYSTEM impersonation. Rustdoc, Python, Node, and CLI `--help` must say so in the same two-tier Chrome 127 / 133 language the native module already uses.

## Open Questions

1. **`extract` return type if a caller needs a domain-reduced, isolation-aware list.** Chosen: `Vec<Cookie>`; use `read` or `extract_report`. Revisit only if a real consumer cannot walk the report.
2. **Windows default `AppBoundPolicy`.** Chosen: `Disabled`. `InjectionOnly` would decrypt v20 without elevation and surprise fewer Chrome 127+ users, at the cost of unsolicited injection. Maintainers may flip it before 0.6.0 without otherwise changing this design; they must **not** flip it to `AllowElevatedFallback`.
3. **Public-suffix list.** Chosen: none; `Site` is (scheme, host). Adding a pinned PSL later is additive — it only widens what matches.

No other open forks: schema stays 1; the bridge is deprecated not deleted; `header` errors rather than merges; `All` is a type-level fact; `AppBoundPolicy` lives on `ExecutionControl`; `read` does not go through the report seam.

## Key Decisions

1. **Ship at 0.6.0.** Every symbol restructured here is prerelease-only; the v0.5.9 surface stays deprecated and working through 0.6.x; deletion is 0.7.0.
2. **The public job surface is a `Source × Shape` matrix**, with `BrowserTarget` / `PathTarget` crate-private and `ExecutionControl` composed once.
3. **`All` is unrepresentable on snapshot and flatten.** `ProfileSelection` cannot express it; `ReportScope` can; `ReportRequest::browser(id)` defaults to All, matching stable `browser_report`.
4. **Three path request types become two**, with Chromium-vs-sniff carried by the credential value.
5. **`read` does not go through `ExtractionReport`.** A crate-private snapshot seam projects `DetailedCookie` for both selections and makes C2 structural.
6. **`DetailedCookie` is the snapshot; `Cookie` is a projection.** `cookies()` stays `-> &[Cookie]`, backed by a cached projection, at the cost of two copies.
7. **`header` takes `SendContext`.** A single partitioned cookie with no matching selector errors; there is no identity-count threshold.
8. **Partition identity is compared in one normalized `Site` space, and `Site` is (scheme, host).** The divergence from browsers is documented, not hidden behind the word "schemeful."
9. **One `Error`** with `Request` / `Stopped` / `Source` / `Engine`, typed `EngineCause` carriers, and no string round-trip for stop classification.
10. **`SessionPolicy` is an acquire-time candidate filter**, default `PersistentOnly`. `read` and `extract` honor it; reports keep session sources.
11. **`AppBoundPolicy` on `ExecutionControl`, default `Disabled`**, raised at the v20 lookup, with `ROOKIE_E2E_APPBOUND_MODE` gated behind `cfg(test)`.
12. **Chromium path constructors cannot be invalid**; the cfg-gated ones live in the `direct_path` allowlisted leaves so `read.rs` stays cfg-free.
13. **`ReadResult.browser_id() -> Option<&str>`.**
14. **Report `schema_version` stays 1.**
15. **Bindings share names and policy strings with Rust**, and every I/O job takes execution control in every language.
16. **The CLI is not projection-only** — `--format detailed` ships with the snapshot change.
17. **Public API snapshots and `deprecated-items.json` change, on purpose, in each PR.**
